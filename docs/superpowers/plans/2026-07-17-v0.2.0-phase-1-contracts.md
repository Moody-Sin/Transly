# Transly v0.2.0 Phase 1 (共享契约与核心协议) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现 Transly v0.2.0 第一阶段目标：在 `crates/transly-core` 与宿主层建立统一的结构化错误类别、有序批量翻译与逐项成功/失败契约、引擎能力描述、取消/超时语义以及与桌面/扩展共享的一致性术语与降级缓存策略，保证现有功能平滑兼容且不回退。

**Architecture:** 严格遵循架构分层原则：在 `crates/transly-core` 中扩展请求契约（单项/批量项带有项唯一标识、顺序保持）、枚举结构化错误种类（Input, Config, Auth, Network, Engine, Timeout, Cancelled, Internal）、引擎能力描述符（EngineCapabilities）与降级缓存防污染标签；在 `src-tauri` 的 IPC (`commands`) 与 HTTP Server 适配层映射上述契约与错误分类，且绝不让核心层依赖 Tauri。

**Tech Stack:** Rust (crates/transly-core, src-tauri, axum, rusqlite, serde, tauri-specta), TypeScript / React (src), Chrome/Firefox Extension (extension).

**Spec:** `docs/superpowers/specs/2026-07-17-v0.2.0-design.md`

## Global Constraints

- 核心分层隔离：翻译、缓存、OCR、术语库、语言检测逻辑必须在 `crates/transly-core`，严禁引入 Tauri 依赖。
- 安全第一：严禁在日志或持久化存储中记录 API Key、配对 Token、完整原文、译文或图像数据。
- 缓存防污染：降级（Fallback）执行或模型切换时，缓存必须以实际生效引擎和配置为索引，防止缓存污染。
- 兼容与不回退：现有 IPC 命令 `translate` 与 HTTP `/translate` 必须保持无损平滑兼容，单测套件和扩展编译必须完全通过。
- 代码规范：全量检查必须通过 `cargo fmt --check` + `cargo clippy --workspace -- -D warnings` + `cargo test --workspace` + `pnpm run lint` + `pnpm run build`。

## Review Focus

- 批量结果顺序错位或丢失项：批量请求包含 N 项时，响应项必须精准对应且顺序一致。
- 逐项部分失败状态：当部分项超时或引擎报错时，必须以 ItemResult::Failed 呈现，不能让整个批次全部抹杀或引发 panic。
- 降级缓存键防污染：通过 FallbackEngine 触发降级后，缓存项的 engine 字段必须准确反映降级后真实执行引擎。
- 取消与超时错误类别映射：取消或超时发生时，错误必须映射为结构化 Error::Cancelled 或 Error::Timeout，而非 generic Internal 字符串。
- 敏感信息泄露防护：错误对象的 Display / serde 序列化绝对不能包含任何密钥或 Authorization 头内容。
