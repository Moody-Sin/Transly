# Transly v0.2.0 Phase 2 (网页翻译体验升级) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现 Transly v0.2.0 第二阶段目标：在浏览器扩展端消费第一阶段的 `items` 结构化契约（精准节点映射与错误类别识别），实现失败项独立重试、主动取消机制（支持保留已译文本）、动态增量平滑更新与批次代际隔离、以及 Popup 重开后对部分失败与可重试项的状态一致性回显。

**Architecture:** 
- `extension/src/content/index.ts`: 引入基于 `id` 的稳定节点映射；在发送批量请求时传递 `items: [{ id, text }]`；消费响应中的 `items: [BatchItemResult]`。对成功的节点安全替换；对失败的节点记录到 `failedItemsMap`，并保留原文不篡改 DOM；支持主动“取消”与“重试失败项”；代际（`currentGeneration`）用于彻底隔离过时响应。
- `extension/src/background/index.ts`: 扩展 `TaskProgressState`，记录失败项计数、错误种类以及可重试状态，维护 Tab 粒度的精确快照。
- `extension/src/popup/index.ts`: 增加“取消翻译”与“重试失败项”交互按钮；支持回显部分失败状态与重试入口。

**Tech Stack:** TypeScript (Chrome Extension MV3 / Firefox WebExtension), DOM APIs, Chrome Messaging.

**Spec:** `docs/superpowers/specs/2026-07-17-v0.2.0-design.md` (阶段二：网页重试、取消、动态更新、还原、状态快照)

## Global Constraints

- 安全第一：严禁扩展保存 API Key，全部流量走 127.0.0.1:39281。
- 原地 DOM 保真替换：原地替换 TextNode，严禁破坏布局；失败节点绝对不得被替换为空文本或篡改。
- 任务代际严格隔离：当用户执行“取消”、“还原”或“重新翻译”时，递增 `generation`，所有在途的异步批次回调彻底失效，杜绝迟到响应污染页面。
- 取消不等于还原：取消操作停止后续批次投递并保持当前已翻译文本；还原操作将全部已翻译文本恢复为原文。
- 质量门禁：必须通过 `cargo fmt --check` + `cargo clippy --workspace -- -D warnings` + `cargo test --workspace` + `pnpm run lint` + `pnpm run build` + `pnpm --filter transly-extension build`。

## Review Focus

- 失败项 DOM 保护：部分批次或单项失败时，对应 TextNode 绝不丢失原文，且在 `failedItemsMap` 中可索引。
- 取消后在途请求拦截：触发“取消”时，进行中的异步网络请求返回后被严格丢弃，不污染已停止翻译的状态。
- 取消与还原的区别语义：用户取消后，页面已有译文依然可见；用户点击还原时，才全部回滚为原始文本。
- 失败项重试幂等性：点击重试时，仅对失败项重新打包发送，成功项不重复请求、不重复计费。
- Popup 重开状态恢复：Popup 关闭并重新打开后，能精准识别当前 Tab 是处于 Translating、Finished、PartiallyFailed 还是 Cancelled，并正确显示“重试失败项”按钮。
