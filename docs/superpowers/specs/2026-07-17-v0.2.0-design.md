# Transly v0.2.0 设计规格

状态：总体方向、功能边界、架构及阶段验收已确认；书面规格待评审。

## 目标与约束

v0.2.0 同时提升网页阅读、桌面快速翻译、专业术语使用、图片翻译及隐私与离线能力。不设固定发布日期，以阶段验收及发布质量为准。采用共享能力优先的架构顺序、按场景交付的开发顺序。

本规格是目标设计，不代表现有实现已具备这些能力。编写实施计划前须核实各入口实际实现及已有测试，优先复用已有请求类型、引擎接口、缓存控制器、扩展任务代际与进度快照，避免重复建设。

核心逻辑位于 crates/transly-core，禁止 Tauri 依赖；src-tauri 承担平台与传输适配；桌面前端通过生成绑定调用；扩展只通过 127.0.0.1:39281 鉴权服务调用。API Key 和配对 Token 继续存储于系统凭据管理器。

## 功能范围

- 共享能力：请求与有序批量结果、结构化错误、引擎能力描述、超时、取消和进度语义；统一术语、缓存及降级策略。
- 网页：动态增量翻译、失败项重试、部分成功反馈、取消、原文还原及 Popup 重开状态一致性。
- 桌面：输入框、划词、剪贴板及浮窗使用一致的加载、结果、错误、重试与取消行为。
- OCR：图片或截图输入、识别、文本翻译、结果展示的完整流程；不包含版面重建。
- 引擎及术语：默认引擎与备用策略、能力及配置检查、术语应用顺序；不包含复杂多引擎对比编辑器。
- 隐私：明确缓存、任务结果、日志及 OCR 图片生命周期，不新增敏感内容明文落盘。
- 离线：技术评估后决定是否纳入正式功能；评估不达标时延期，不阻塞其他阶段发布。

## 架构与职责

### 核心层

定义或复用翻译请求、批量结果、错误类别、引擎能力及进度事件类型。执行语言校验、术语处理、缓存策略及引擎调用。批量结果以稳定项标识对应输入，保持顺序，成功与失败逐项表达。核心不管理窗口、浏览器标签页或系统凭据。

任务状态类型可以共享；任务实例、ID、生命周期及资源调度由宿主或入口适配层持有。不得为统一状态引入全局持久任务系统。

### 宿主层

IPC 和 HTTP 将请求转换为相同核心入口。宿主处理凭据、并发限制、取消信号、系统剪贴板与平台 OCR，并映射传输错误及进度。复用现有缓存控制器的关闭、清空和在途写回保护。

### 桌面及扩展

桌面 UI 维护交互状态，不复制核心引擎和缓存规则。扩展后台维护标签页任务快照；Content Script 管理节点、原文、替换及还原；Popup 展示状态并发出操作。节点代际及页面归属校验仍留在扩展，不能用共享任务状态替代 DOM 安全校验。

OCR 是翻译输入适配：平台识别结果转成文本后调用共享流程。平台实现保持隔离；具体已有 OCR 实现的位置和能力须在实施计划中核实。离线引擎复用现有引擎接口。

## 状态、错误与恢复

状态为 Idle、Queued、Running、Succeeded、PartiallyFailed、Failed、Cancelled。Queued 仅用于确有受控等待的入口；已有超载立即拒绝策略不得改为无界排队。结束状态不再次应用旧结果；新操作使用新任务代际。

取消后停止投递新批次，支持时中止在途请求，否则丢弃迟到结果。取消不等于还原：已应用译文保持，用户通过还原操作恢复原文。还原同时使旧任务结果失效并停止增量监听。

重试只针对失败项；成功项不重复计费或覆盖。恢复前核实任务代际及节点仍有效。动态增量批次更新计数与快照，不回写已结束旧任务。

错误类别包括输入、配置、鉴权、网络、引擎、超时、取消及内部错误。UI 根据类别提供提示，不匹配后端错误字符串；日志不得记录密钥、Token、完整原文、译文或图片。超时参数复用现有合理配置；具体预算在实施计划依据现有实现确定。

术语及降级策略必须由桌面和扩展共享。实际响应应标识执行引擎；缓存使用实际引擎及必要配置标识，防止降级和模型切换污染。

## 阶段与验收

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| 一 | 共享契约、任务语义、IPC/HTTP 迁移；引擎配置、术语及隐私策略一致性 | 旧功能不回退；顺序、部分失败、取消、超时、缓存与降级检查通过 |
| 二 | 网页重试、取消、动态更新、还原、状态快照 | 静态页、SPA、部分失败、Popup 重开、重复任务及迟到结果端到端验证通过 |
| 三 | 四类桌面入口一致行为；引擎与术语配置体验 | 输入、划词、剪贴板、浮窗的成功、失败、重试及取消场景通过 |
| 四 | 图片/截图 OCR 翻译闭环 | 识别错误与翻译错误可区分；无假成功；取消和图片生命周期可验证 |
| 五 | 离线引擎评估，达标后最小接入 | 模型体积、启动、内存、延迟、质量及平台支持有可复现测量和明确结论 |
| 六 | 发布收口 | 平台验证、性能、安全、文档、更新日志及候选版本验证完成 |

离线评估须在下载或引入模型前确定测试设备、语言对、测试语料、资源预算及许可证条件。先提出数值验收门槛并评审，再测量与决定接入；本规格不虚构未经调研的资源或质量指标。离线执行不得静默回退云端。

## 验证与发布门禁

优先复用现有测试，新增针对真实行为和竞态的回归检查，避免逐函数镜像测试。核心验证结果顺序、状态、失败、取消、超时、术语、缓存隐私及降级。宿主验证两个传输入口的一致性、鉴权、并发和尺寸限制。端到端使用可控制延迟和失败的 mock 引擎，不调用商业 API。

必须通过 cargo fmt --check、cargo clippy --workspace -- -D warnings、cargo test --workspace、pnpm run lint、pnpm run build、扩展构建、生成绑定一致性及密钥扫描。完成 Windows、macOS、Linux 对应构建和可用流程验证，明确平台限制；Firefox 支持以实际兼容验证为准，不仅以 manifest 或 Origin 支持为依据。

安全复核覆盖 Token 轮换、CORS/CSP、缓存禁用期间的在途写回、日志内容、图片临时资源释放以及离线模式无外发。性能测量必须记录环境、语料、引擎、缓存状态及网络条件，不承诺未经测量的毫秒级外部翻译。

## 评审交接

书面规格通过后编写实施计划：核实源码现状、列出最小改动文件、依赖关系、具体操作和可运行验收命令。工作角色为评审与规划；本规格不授权产品代码实现或发布。
