# `tests` —— 需要真实系统能力的集成测试

单元测试与源码同文件（各模块底部 `#[cfg(test)]`）。这里只放**必须触碰真实外部依赖**
的测试：它们无法在纯逻辑层断言，模拟也证明不了什么。

## 目录

| 文件 | 覆盖 | 运行平台 |
|---|---|---|
| `ocr_e2e.rs` | 造已知布局的图 → 真实 OCR → 断言块坐标落在正确象限 | Linux（tesseract） |

## 为什么 `ocr_e2e.rs` 只在 Linux 跑

它是唯一能捕获「坐标轴搞反」「y 翻转漏做」「归一化分母用错」的测试——纯坐标单测
覆盖不到「引擎返回像素框」这一段真实链路。

Windows（`Windows.Media.Ocr`）与 macOS（Vision）走系统 API，CI 机器无法保证装了
相应语言包，跑起来会因缺语言数据而假失败，故用 `#![cfg(all(not(windows), not(macos)))]`
限定。这两个分支的坐标映射正确性依赖实现时的真机核对与 `ocr/geom.rs` 的纯函数单测。

## 硬约束

- **不依赖系统字体**：`draw_text` 用内置 5×7 点阵字模，避免不同发行版字体缺字导致
  识别结果漂移。新增字符时同步补字模，别改成用系统字体渲染。
- **断言坐标而非文本**：OCR 识别出的文字串在不同 tesseract 版本间不稳定，
  但「块落在哪个象限」是稳定的。断言文本会让测试在升级依赖后无意义地红。
- **CI 必须先装 tesseract**：`ci.yml` 的三处 apt 清单都含 `tesseract-ocr` /
  `tesseract-ocr-chi-sim` / `tesseract-ocr-eng`，漏装即红。
